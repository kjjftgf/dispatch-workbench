# 配送运营工作台 · Dispatch Workbench

一屏看站点外卖配送运营的本地看板：**今日总览 / 实时看板 / 质量目标**三个板块，60 秒自动刷新，数据直接从蜂鸟风神（Aeolus）后台实时抓取。

> 本项目只是采集与展示工具：**不含任何账号、Cookie、密钥，也不含任何站点/骑手数据**。要跑起来必须自己有可以登录 Aeolus 的账号。
> 版本号是 `oss-x.y.z`，与 Gitee 上安装包的 `vX.Y` 不是同一套序列。

---

## 功能

| 板块 | 内容 |
|---|---|
| **今日总览**（值班屏） | 运力缺口（应排−实出）、时段达标率（全时段加权）、未达标骑手、今天的时间轴（九段）、翻盘测算、从早到晚事件流 |
| **实时看板** | 全天达成、尖峰天贡献、时段达成、档位达成、准时率、橙色风暴抽检、不满意单明细、服务质量 KPI、订单识别 |
| **质量目标** | KPI 目标值（妥投率 / T8 / 不满意率 / 复合超时）× 12 场景，支持上传 Excel、手填、恢复默认 |

附带一个可选的「只读预览链接」：把工作台打包成不可读页面，生成带有效期和水印的链接给同事看（需要 node，见下）。

---

## 前提

1. **Aeolus 账号**：本工具不提供数据，只是把你后台已经能看到的数据聚合到一屏。
2. **Chrome / Chromium**：首次运行会拉起一个独立的调试浏览器实例，你在里面登录 Aeolus；工作台通过 CDP 读它的登录态。
   - 调试端口默认 **9224**（避开常见工具占用的 9223）
   - 这个实例和你的日常浏览器隔离：**不要在两边同时登录同一个账号，会互相顶号**
3. **Python 3.9+**，依赖只有 `openpyxl`（解析导出的 xlsx）。

## 快速开始

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python run.py            # 默认 60 秒刷新
# 打开 http://127.0.0.1:8765/
```

首次运行会：

1. 释放内置页面到 `data/`（已存在不覆盖，改版式直接改 `data/*.html`）
2. 拉起调试浏览器 → 在里面 **登录 Aeolus**
3. 选择站点，写入 `~/.dispatch_assistant_config.json`（`team_id` / `team_name`）
4. 开始按 60 秒轮询

单次取数（不常驻）：

```bash
.venv/bin/python refresh.py
```

**首轮取数要几十秒**，这之前页面会显示「读不到看板数据，60 秒后重试」——不是报错，是第一轮还没跑完。

## 运行时的几个既定行为

| 行为 | 说明 |
|---|---|
| **端口固定 8765** | 被占用会退到 8766 并打印警告；此时手机/其他电脑连不上，先释放 8765 |
| **夜间静默 02:00–06:00** | 不抓数、关掉浏览器省内存，06:00 后自动恢复。夜里没数据是正常的 |
| **Ctrl+C 退出** | 会关掉自己起的调试浏览器；同一台机器若还有别的实例共用 `~/.dispatch_assistant_chrome`，它的浏览器也会被关（下轮自动重开） |
| **一台机器一个实例** | 同一个 `~/.dispatch_assistant_chrome` 只能被一个进程占用，跑两个会互相抢 |
| **局域网访问要密码** | 绑 0.0.0.0；本机 127.0.0.1 免密，其他设备必须输密码（页面「🔑 设置密码」可改） |

## 口径（重要，别改错）

- **档位达成**：单量与时长**双达**「取低原则」——从最高档往下找，第一个两项都满足的档位；0 = 未达标。
- **时段达标率**：**全时段加权**（未开始的时段按 0%，无排班的时段按 100%），权重按考核方案。
- **结算门槛（双门槛，任一不达 → 当日不结算基础服务费）**：时段达标率 ≥ 时段门槛 **且** 达标人数 ≥ 应排 × 规模门槛系数；封顶 = 应排 × 110%。
- **时段**：后台只有 9 个时段（凌晨2 / 凌晨3 合并计），时段标准见 `modules/realtime_board.py` 的 `SHIFTS`。
- **有效完单**：剔除改派/无效单后再判定，不直接用原始单量。

## 每月要手动配的东西（系统拉不到的）

后台能拉的只有「档位标准 / 难度等级 / 规模门槛系数 / 时段门槛」，其余三样必须人工维护：

| 项目 | 位置 | 说明 |
|---|---|---|
| **KPI 质量目标**（12 场景 × 4 指标） | `data/kpi_targets.json`，或看板「⚙ KPI指标」上传 Excel | 后台没有这套目标值接口。仓库里的 `kpi_targets.example.json` 只是示例，**用前必须按本月考核方案核对** |
| **恶劣天气分层切点** | `modules/realtime_board.py` 里 `weather_level` 分类 | 后台只给每单天气等级，分层规则（正常/轻微/一般/严重1/2/3）在方案里，需人改 |
| **时段标准与权重** | `modules/realtime_board.py` 的 `SHIFTS` | 各时段时长/单量/权重、以及个别时段的特殊要求 |

档位标准是运行期自动取的（后台「月度运力标准」当月行），但 `LEVELS` 里留了一份兜底值，**API 失败时会静默用兜底** —— 换月记得同步，否则偶发退回旧口径。

## 只读预览链接（可选）

「🔗 预览链接」需要 node：

```bash
cd tools && npm install
```

原理：把 `data/` 下的页面压缩 + JS 混淆成不可读产物放 `data/_protected/`，用 `/s/<token>` 发链接，可设有效期、可撤销，页脚带水印可溯源。对外地址前缀写 `data/share_base.txt`（如你的 frp 域名）。

**先把对外地址写进 `data/share_base.txt`**（例如 `https://board.example.com`，经 frp/内网穿透指到本机 8765），否则生成的链接是 `127.0.0.1`，发给别人打不开——页面会直接给提示。

## 为什么没有「安全台账」

安全台账（餐箱消毒 / 骑手测压 / 三级教育卡）涉及骑手健康与培训记录，各站数据不同、且不适合随代码分发，所以开源版不含。想要的话自己在 `data/` 下生成 `data/safety.html` 即可接入外壳。
